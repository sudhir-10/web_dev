================================================================================
HOTEL MANAGEMENT SYSTEM - API REFERENCE
================================================================================

BASE URL: http://localhost:5000/api

AUTHENTICATION:
For all endpoints except login/register, include this header:
  Authorization: Bearer <your_jwt_token>

CONTENT TYPE:
All requests and responses use JSON:
  Content-Type: application/json


================================================================================
AUTHENTICATION ENDPOINTS
================================================================================

1. LOGIN
--------
Authenticate user and receive JWT token

Endpoint:  POST /auth/login
Method:    POST
Auth:      Not required

Request:
{
  "email": "admin@hotel.com",
  "password": "admin123"
}

Response (Success 200):
{
  "success": true,
  "message": "Login successful",
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": {
    "id": 1,
    "email": "admin@hotel.com",
    "name": "Administrator",
    "role": "admin"
  }
}

Response (Error 401):
{
  "success": false,
  "message": "Invalid email or password"
}


2. REGISTER
-----------
Create new user account

Endpoint:  POST /auth/register
Method:    POST
Auth:      Not required

Request:
{
  "email": "newuser@example.com",
  "password": "password123",
  "name": "John Doe",
  "role": "guest"
}

Response (Success 201):
{
  "success": true,
  "message": "User registered successfully",
  "userId": 5
}

Response (Error 400):
{
  "success": false,
  "message": "Email already registered"
}

Validation:
- Password minimum 6 characters
- Email must be unique
- Role must be: admin, staff, or guest


3. GET CURRENT USER
-------------------
Retrieve authenticated user information

Endpoint:  GET /auth/me
Method:    GET
Auth:      Required

Response (Success 200):
{
  "success": true,
  "user": {
    "id": 1,
    "email": "admin@hotel.com",
    "name": "Administrator",
    "role": "admin"
  }
}


4. CHANGE PASSWORD
------------------
Change password for authenticated user

Endpoint:  POST /auth/change-password
Method:    POST
Auth:      Required

Request:
{
  "currentPassword": "oldpassword123",
  "newPassword": "newpassword123"
}

Response (Success 200):
{
  "success": true,
  "message": "Password changed successfully"
}

Response (Error 401):
{
  "success": false,
  "message": "Current password is incorrect"
}

3. CREATE ROOM
--------------
Create new room (Admin only)

Endpoint:  POST /rooms
Method:    POST
Auth:      Required (Admin only)

Request:
{
  "room_number": "106",
  "type": "suite",
  "price_per_night": 200,
  "capacity": 4,
  "description": "Luxury suite with living area"
}

Response (Success 201):
{
  "success": true,
  "message": "Room created successfully",
  "roomId": 6
}

Required Fields:
- room_number (text, unique)
- type (single|double|suite)
- price_per_night (number, positive)
- capacity (number, positive)

Optional Fields:
- description (text)


4. UPDATE ROOM
--------------
Modify room details (Admin only)

Endpoint:  PUT /rooms/:id
Method:    PUT
Auth:      Required (Admin only)

Example:   PUT /rooms/1

Request (partial updates supported):
{
  "price_per_night": 150,
  "status": "maintenance",
  "description": "Updated description"
}

Response (Success 200):
{
  "success": true,
  "message": "Room updated successfully"
}


5. DELETE ROOM
--------------
Delete room (Admin only). Cannot delete if active bookings exist.

Endpoint:  DELETE /rooms/:id
Method:    DELETE
Auth:      Required (Admin only)

Example:   DELETE /rooms/1

Response (Success 200):
{
  "success": true,
  "message": "Room deleted successfully"
}

Response (Error 400):
{
  "success": false,
  "message": "Cannot delete room with active bookings"
}

3. CREATE BOOKING
-----------------
Create new reservation

Endpoint:  POST /bookings
Method:    POST
Auth:      Required

Request:
{
  "room_id": 1,
  "check_in": "2024-02-01",
  "check_out": "2024-02-05",
  "special_requests": "Early check-in if possible"
}

Response (Success 201):
{
  "success": true,
  "message": "Booking created successfully",
  "bookingId": 5,
  "totalPrice": 400,
  "nights": 4
}

Response (Error 400):
{
  "success": false,
  "message": "Room is not available for the selected dates"
}

Required Fields:
- room_id (number)
- check_in (YYYY-MM-DD)
- check_out (YYYY-MM-DD)

Optional Fields:
- special_requests (text)

Validation:
- check_out must be after check_in
- Room must be available for dates
- System auto-calculates total price

================================================================================
HTTP STATUS CODES
================================================================================

200 OK - Request successful
201 Created - Resource created successfully
400 Bad Request - Invalid request data or validation failed
401 Unauthorized - Authentication required or invalid token
403 Forbidden - Insufficient permissions for requested action
404 Not Found - Resource does not exist
500 Internal Server Error - Server error occurred


================================================================================
ERROR RESPONSE FORMAT
================================================================================

All error responses follow this format:

{
  "success": false,
  "message": "Detailed error message"
}

Common Error Messages:
- "No token provided"
- "Invalid or expired token"
- "Authentication required"
- "Insufficient permissions"
- "Email already registered"
- "Invalid email or password"
- "Room is not available for the selected dates"
- "Room not found"
- "User not found"
- "Booking not found"


================================================================================
CURL EXAMPLES
================================================================================

Login:
curl -X POST http://localhost:5000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@hotel.com","password":"admin123"}'

Get Rooms (replace TOKEN with actual token):
curl -X GET http://localhost:5000/api/rooms \
  -H "Authorization: Bearer TOKEN"

Create Booking:
curl -X POST http://localhost:5000/api/bookings \
  -H "Authorization: Bearer TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "room_id": 1,
    "check_in": "2024-02-01",
    "check_out": "2024-02-05"
  }'

Get Available Rooms:
curl -X GET "http://localhost:5000/api/rooms/available/search?check_in=2024-02-01&check_out=2024-02-05" \
  -H "Authorization: Bearer TOKEN"


================================================================================
RATE LIMITING
================================================================================

Currently no rate limiting is implemented.
For production, consider:
- Limit requests per IP
- Limit requests per user
- Implement timeout handling
- Set up API throttling


================================================================================
NOTES
================================================================================

1. All timestamps are in ISO 8601 format (YYYY-MM-DDTHH:MM:SS.SSSZ)
2. All prices are in USD and use DECIMAL format
3. Dates use YYYY-MM-DD format
4. JWT tokens expire after 24 hours
5. Guest profiles are auto-created when guest makes first booking
6. Room availability considers all pending and confirmed bookings
7. Bookings with overlapping dates on same room are prevented
8. Cascade delete is enabled (deleting user deletes all related data)
